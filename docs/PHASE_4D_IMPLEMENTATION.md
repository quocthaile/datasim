# Phase 4D Implementation: PDF-to-Simulation End-to-End Validation

## 1. Overview

Phase 4D connects the existing deterministic PDF table extraction adapter (`datasim_pdf`), the candidate-only evidence intake boundary (`datasim_intake`), the reviewed component domain model (`datasim_component`), the knowledge-driven vertical slice (`datasim_vertical`), and the real `ngspice` simulation backend (`datasim`) in an end-to-end integration and validation gate.

This phase is an incremental integration and verification milestone. No new libraries or public production APIs were added, and all existing Phase 1–4C public contracts and numerical tolerances (`0.05 V`, 1% of the `5 V` step amplitude) are preserved.

## 3. End-to-End Integration Architecture

The Phase 4D gate (`run_pdf_to_simulation_gate`) reuses the existing deterministic synthetic PDF fixture (`tests/fixtures/synthetic_datasheet.pdf`, generated by `tests/fixtures/make_synthetic_datasheet_pdf.py`) and traverses every existing boundary in sequence:

1. **Real Poppler Extraction (`datasim::pdf::extract_electrical_table`)**:
   - Executes `pdfinfo` and `pdftotext -bbox-layout` on Page 0 (`TABLE_R`, fictional resistor `SIM-R-10K`, printed page `"5"`) and Page 1 (`TABLE_C`, fictional capacitor `SIM-C-1UF`, printed page `"Appendix C-2"`).
2. **Intake Validation & Candidate Bundle Construction (`datasim::intake::validate_intake_manifest`, `build_candidate_bundle`)**:
   - Retains the `IntakeManifest`, `IntakeReport` diagnostics (`conflict_candidate` on Page 0 Row 1 vs. Row 3 at `T_A=25 degC; V_DD=5 V`; `ambiguous_numeric_text` on Page 1 Row 1 `"1,000"`, Row 2 `"1.0*"`, and Row 4 blank unit), and cell-level `EvidenceLocation` provenance (`pdf_page_index`, `printed_page_label`, `table_or_figure_id`, `cell_or_region`, `footnote_refs`).
   - Verifies that all 9 resistor observations and all 11 capacitor observations enter `datasim_component` strictly in `ReviewState::candidate` with empty `review_history`, `knowledge == std::nullopt`, and `models.empty()`.
3. **Synthetic Engineering Review & Conflict Preservation (`datasim::component::apply_review_decision`)**:
   - Transitions all observations through `candidate -> needs_review` (`ActorKind::automated_check`) and `needs_review -> approved` or `needs_review -> rejected` (`ActorKind::human_engineer` synthetic test fixture reviewer).
   - Preserves all 9 resistor observations and all 11 capacitor observations in `bundle.observations`.
   - Records the `T_A=25 degC; V_DD=5 V` resistor conflict (`10.0 kohm` in Row 1 vs. `10.01 kohm` in Row 3) explicitly in `ComponentKnowledge::conflicts` (`conflict.pdf.resistor.r_dc.25c`, `ConflictResolutionStatus::resolved_by_review`, selecting Row 1 and rejecting Row 3).
   - Rejects and retains the capacitor's ambiguous comma-grouped row (`"1,000"`), footnote-qualified row (`"1.0*"`), and blank-unit row (Row 4).
4. **Condition-Compatible Selection & Explicit SI Normalization (`make_normalized_parameter`, `promote_parameter_to_knowledge`)**:
   - Selects the only unambiguous, condition-compatible nominal operating row shared across both tables (`T_A=85 degC`):
     - Resistor Row 2 (`SIM-R-10K`, `T_A=85 degC`): `Min = 9.8 kohm -> 9800.0 ohm`, `Typ = 10.0 kohm -> 10000.0 ohm`, `Max = 10.2 kohm -> 10200.0 ohm`.
     - Capacitor Row 3 (`SIM-C-1UF`, `T_A=85 degC`): `Min = 0.9 uF -> 9.0e-7 F`, `Typ = 1.0 uF -> 1.0e-6 F`, `Max = 1.1 uF -> 1.1e-6 F`.
5. **Model Binding & Compatibility Verification (`ModelArtifactDescriptor`, `ModelValidationRecord`, `CircuitAssembly`)**:
   - Binds synthetic `analytical_equation` models (`model.synthetic.pdf.resistor.ohmic-linear` and `model.synthetic.pdf.capacitor.ideal-linear`) and `validated_within_envelope` validation records referencing the PDF `EvidenceId`s.
   - Assembles `circuit.pdf.synthetic.rc-lowpass-v1` (`R = 10000.0 ohm`, `C = 1.0e-6 F`, $\tau = 10\,\text{ms}$) and validates it via `validate_circuit_assembly()` and `prepare_vertical_rc_simulation()`.
6. **Real `ngspice` Execution, Manual `RcConfig` Comparison & Provenance Verification (`execute_vertical_rc_run`, `execute_rc_run`)**:
   - Executes `execute_vertical_rc_run()` against real `ngspice` under `ExecutionPolicy::test_only_synthetic`.
   - Executes an equivalent manual `RcConfig` (`resistance_ohm = 10000.0`, `capacitance_F = 1.0e-6`, default `0 -> 5 V` step stimulus and `6 ms` transient window on the 4001-sample common grid).
   - Verifies zero sample-by-sample waveform difference (`0.0 V`), analytical step-response agreement well within `0.05 V`, byte-identical `results.csv`, `errors.csv`, `circuit.cir`, and `validation_report.json`, and complete PDF-to-simulation lineage in `provenance_metadata.json`.
